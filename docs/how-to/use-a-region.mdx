# Use the EU or US region

import { Steps, Tabs, TabItem, Aside } from '@site/components';

Route chat requests and the model catalog through Mistral's EU or US endpoint — for example, to keep inference inside the EU.

## Prerequisites

- The `pi-mistral-native` package installed
- An API key configured ([Set up your API key](/how-to/set-up-api-key/))

<Steps>

1. Set the region. Pick one method:

   <Tabs syncKey="config-method">
   <TabItem label="Command">

   ```
   /mistral set endpoint.region eu
   ```

   </TabItem>
   <TabItem label="File">

   Add this to your [user config file](/reference/config-files/):

   ```json
   { "endpoint": { "region": "eu" } }
   ```

   </TabItem>
   <TabItem label="Environment">

   ```sh
   export MISTRAL_REGION=eu
   ```

   Ignored if any config file sets `endpoint.region`. The value must be exactly `eu`, `us` or `global` — case-sensitive.

   </TabItem>
   </Tabs>

2. Run `/mistral` and check that `endpoint.region` shows `eu`.

3. Run `/mistral test` to confirm the regional endpoint answers.

4. Start a chat and pick a `mistral-native/…` model.

</Steps>

:::caution[Only chat moves to the region]
Knowledge tools, server-side tools, agent mode and connectors keep using the global endpoint — those services are not available regionally. Regional token prices are 10% higher.
:::
